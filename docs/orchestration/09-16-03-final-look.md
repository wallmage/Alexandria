# R38 — remedy truth (W10 audit of every printed family, `<scratchpad>/fleet8/w10.final.txt`)

Audit result: 80 message families; the printed Fix clears the line for 22, partially for 25, never for 33. Mechanism: `alx.py` "adopt" (~line 663) rewrites producer Fixes into canned commands per family (`--iter`, bare `source set`, `alx issue`, `merge coverage.json`) and `_ref` wraps a dozen unrelated ledger rules into `ledger/reference` with one Fix (`set field supports`). This is why a GLM-class model loops: it executes the printed remedy and the line stays.

## Rulings

- R38.0 Truth rule (binding on every family, now and later): a printed Fix is a command or an edit that, executed literally, clears the line. Never: a flagless `alx source set S<n>`; `alx review start <kind> --iter` for a note-quality or stale line; `alx issue` / `alx check` for a condition they do not change; a file name that does not exist unless the Fix says to write it. Adopt fills a Fix only when the producer printed none; it never replaces a producer Fix.
- R38.1 `ledger/reference` catch-all dissolved: each rule carries its own Fix — `evidence_of_absence` → `set field evidence_of_absence in claims/<file>, then alx claim add claims/<file>`; unknown id → `remove <id> from <field>`; `as_of` drift → `set field as_of …`; empty assumptions → `set field assumptions …`; circular supports → `remove <id> from supports`; high-priority coverage per R37.8. Family name may stay `ledger/reference`; the Fix is per rule.
- R38.2 Source-classification lines (`ledger/key-claim`, `ledger/portfolio`, `ledger/source-family`, `ledger/undated-reason`, `ledger/provenance` interested-coverage/bare-set variants): Fix names the flag and what to write. key-claim: `fetch an independent page for C7, add it to source_evidence and alx claim add; or set field importance "supporting" and re-add`. source-family / host-conflict: `write ≥40 characters on why these pages are one/two parties into family-justification.txt, then alx source set S19 --family-justification family-justification.txt`. undated-reason: `write why the page is continuously updated into undated-reason.txt, then alx source set S<n> --undated-reason undated-reason.txt`. portfolio/provenance: `alx source set S<n> --provenance primary_independent only if the page truly is; otherwise fetch an independent one`.
- R38.3 `ledger/quantity` Fix: `alx find S13 53 — paste that window into extract_or_location and alx claim add, or reword the claim` (surface form per R37.6).
- R38.4 Patch-file Fixes: `ledger/coverage` → `set coverage[i].claim_ids to supported claim ids in a patch file, then alx ledger merge <patch>`; `ledger/synthesis` → `put C1 C2 … in synthesis.central_judgment_claim_ids in a patch file, then alx ledger merge <patch>`; notes-shape lines at check carry the same. No `alx check --fix`, no `coverage.json`/`people.json`/`ledger-patch.json` names unless the line says "(write it)".
- R38.5 Review lines: `review/<kind>-stale` Fix → `re-read the changed paragraphs, then alx review finish <kind>`; `content/score`, `content/check` quality lines, `content/critical-finding`, `content/disclosure` Fix → `edit reviews/content.json (<what: raise the score / set checks true / fill sections / disposition fixed / excerpt ≥40 chars from report.md>), then alx review finish content`; `review/<kind>-missing` Fix → `alx review start <kind>` only when no iteration exists, else `alx review finish <kind>`. `review start` without `--iter` on a non-blank note refuses (exit 0, one line: `reviews/<kind>.json already has content — alx review finish <kind> attests it; --iter starts a new blind read and moves it to reviews/<kind>.iter<N>.json`); with `--iter` the old note is moved aside, never deleted. `content/language`: drop when `brief.report_language` is absent (workspace lang wins); Fix otherwise `set brief.report_language "<lang>" in a patch file, then alx ledger merge <patch>`.
