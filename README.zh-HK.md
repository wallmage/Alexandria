# Alexandria

Alexandria 的名字來自亞歷山大圖書館。那座圖書館曾立志匯聚世間一切知識。我開發這個項目，亦懷着同一份心意：古今中外、宇宙萬物，凡是你想弄清楚的，都值得深入研究。

**交給 Alexandria 一個題目，它會為你組成一個研究編輯部。遇上複雜題目，團隊可以查閱數百個資料來源，逐一評估可信程度、追溯原始證據、交叉核實，再由總編輯寫成長篇報告，交代事情的來龍去脈，讓每項關鍵判斷都有據可查。**

題目可以是古代歷史、當代科技、人物生平，也可以是哲學思想。Alexandria 會按題目選擇研究框架，安排多輪搜尋。搜集回來的資料須經篩選和核實，才會成為報告的依據。團隊亦會主動尋找足以推翻結論的反證。十個網站轉述同一篇報道，只算一個來源。官方說法與獨立證據要分清楚，未能解決的分歧則須交代會如何影響結論。

這些工夫貫穿研究和寫作。動筆前先整理證據與推論，交稿前優先抽查關鍵結論所引的原文，全文再經 Rewild 去 AI 味及八項內容評審。報告要解釋原理、因果和取捨，也要容納有分量的反對意見。你可以沿着引用核對依據。完成內容後，系統會配上適合題目的版式，交付 PDF 和可編輯的 Markdown 原稿。

[簡體中文](README.md) · [English](README.en.md) · [繁體中文（香港）](README.zh-HK.md)

Alexandria 可研究任何題目，沒有固定的選題限制，志向是匯聚全世界的知識。交付走 `alx`：init → fetch → claim add → check → snapshot → review → issue → render，預算 30 分鐘。剩餘時間不足 8 分鐘時執行 `alx issue`，再執行 `alx render`。成品是專業製作的 PDF，配有緊貼相關事實的引用。

## 題目不同，追問的問題也不同

研究明朝財政，與研究一間晶片公司或一套哲學思想，所需的證據和切入點各有不同。Alexandria 內置六類研究框架，按研究對象選用。跨領域題目則結合相關範疇。

| 研究對象 | 要追問甚麼 |
|---|---|
| **人物** | 成長背景如何影響選擇？哪些決定改變了人生方向？成就與爭議，跟所處時代有甚麼關係？ |
| **組織** | 如何成立、如何演變？內部怎樣運作？憑甚麼競爭？利益和權力怎樣分配？ |
| **產品、技術與作品** | 核心原理是甚麼？經歷過哪些改變？實際效果如何？相比其他選擇，有甚麼優點和限制？ |
| **事件** | 甚麼條件促成事件？導火線是甚麼？各方採取了甚麼行動？影響如何延續至今？ |
| **概念、理論與方法** | 最初想解決甚麼問題？核心邏輯如何成立？其後怎樣發展？哪些批評和反例最有力？ |
| **行業、制度與系統** | 規則怎樣運作？資金、資訊和權力如何流動？誰得益，誰付出代價？改變由甚麼推動？ |

選好框架，便列出要回答的問題，訂明先查甚麼、需要哪些證據，以及怎樣才算查得足夠。可能左右結論的問題會優先處理。

框架用來查漏，章節則按題目編排。歷史報告可以沿關鍵轉折推進。技術報告可以先解釋原理，再談實際限制。

## 總編輯統籌，研究員分頭查證

你直接交代任務的 AI 是**主智能體**，在這個編輯部裏擔任總編輯。它會將具體的調查工作交給其他 AI 助手。這些助手稱為**子智能體（sub-agent）**，相當於研究員。每位研究員按分工搜尋資料、核對證據，再向總編輯提交結果。

總編輯要先釐清報告要回答甚麼，才分派工作。同一題目可以由幾位研究員同時跟進：有人追查歷史和原始紀錄，有人核對最新數據與實際表現，另有人專查爭議、失敗案例和相反證據。研究員各有明確範圍。總編輯負責掌握全題，判斷哪些材料足以支持結論，哪些地方仍要補查。

主智能體和子智能體就是這樣分層協作。你提出題目後，Alexandria 會處理分工和綜合分析。運行環境支援多智能體時，調查可以同步進行。未能並行時，仍會按同一計劃逐項完成。

搜尋會由題目名稱、別名及專門術語入手，查找論文、檔案、財務報告、公開數據等原始資料。獨立報道、當事人的經驗，以及其後的修訂或撤回紀錄亦在調查範圍內。有需要時，會用資料的原有語言搜尋。

研究員交回的結果包括證據、出處、互相矛盾之處、待解問題和初步分析。總編輯整合資料、剔除重複來源，再決定哪些發現可以互相印證、哪些尚待查證，並對最後的論證負責。

調查規模隨題目而定，沒有固定的來源數量要求。關鍵問題須有證據支持，未能查清的地方須記下分歧及資料缺口。亦要確認繼續搜尋已不再改變判斷，才結束調查。

## 來源是否可信，要看它能證明甚麼

### 五類來源背景，配合證據類型判斷

Alexandria 會先辨別資料與研究對象的關係，分成五類來源背景：

| 來源背景 | 核實重點 |
|---|---|
| **第一手、獨立** | 是否直接掌握證據？研究或紀錄方法是否可靠？ |
| **第一手、有利益關係** | 官方文件、廠商數據和當事人陳述能證明甚麼？哪些只是自身說法？ |
| **第二手、獨立** | 有沒有自行調查？解釋能否追溯至原始證據？ |
| **第二手、依賴其他報道** | 是否只轉述同一份資料？有沒有額外核實？ |
| **匿名、無法核實或轉載** | 原始出處在哪裏？能否驗證？是否只能作為調查線索？ |

證據類型亦會分開處理，包括財務披露、同行評審研究、預印本、官方文件、獨立測試、新聞採訪、意見及宣傳資料。評估後，再就具體判斷標示高、中或低可信度。

權威性與獨立性是兩回事。財務報告可以支持已披露的營業額，卻不能直接證明產品較好。企業公告可以證明公司提出了某項計劃，卻不能證明計劃可行。知名傳媒轉述別人的報道，也不會因此多出一份獨立證據。

### 十篇報道，未必有十個獨立來源

十個網站轉載同一篇文章，仍然只有一個來源。同一機構的多個網頁，或採用同一數據集的多項研究，也不能直接當成多方印證。

Alexandria 會歸併這些共同來源。關鍵判斷要獲得充分交叉核實，至少須有兩組互相獨立的來源支持，其中至少一組獨立於研究對象。證據不足，結論的可信度就要相應降低，並交代限制。

資料互相衝突時，先核對日期、定義、樣本和利益關係，再追查原始紀錄及後續更正。能釐清的，要解釋採信哪一方及理由。未能釐清的，則保留分歧，說明對結論的影響。

### 反證也是調查的一部分

確認核心判斷前，Alexandria 會提出最有力的另一種解釋，再搜尋能夠分辨兩者的證據。失敗案例、負面結果、適用限制和當事人的反對意見，都要納入研究。

例如，要判斷一項技術是否領先，除了查找支持其表現的測試，也要檢查測試條件、失效情況和替代方案。最終判斷須經得起這些反證的考驗。

### 證據整理好，才開始寫

重要說法會建立相應紀錄，列出原文摘錄或位置、來源、日期、可信程度、相關矛盾，以及由證據推導判斷的過程。事實、當事人主張、估算與分析分開記錄。

動筆前，先核對引文、清理重複來源、處理爭議，並標明資料缺口。交稿前會優先抽查關鍵結論的網上原文，確認所引頁面確實載有相關證據。可能變動的資訊，亦須檢查是否仍然適用。

## 歷史要見時代，傳記要見選擇

Alexandria 內置六種寫作模式，中英文均可使用。總編輯按題目定下主要文體，決定從哪裏入手、哪些材料值得詳寫，以及怎樣將證據寫成讀者容易理解的解釋。

你可以用熟悉的作者或專業寫作方法，說明想要的文風。中文歷史研究，可以參照**黃仁宇**從制度和時代條件理解人物選擇的分析方法。英文人物傳記，可以參照 **Walter Isaacson** 圍繞關鍵選擇組織人物經歷的方法。這些名字指的是寫作方法，文章由智能體根據已查證的資料撰寫。

| 寫作模式 | 題材例子 | 怎樣寫 |
|---|---|---|
| **歷史型** | 中文歷史，如明朝財政 | 從白銀入手，追問財政制度、貿易和地方管治如何互相影響，再將人物的選擇放回當時環境理解。交代關鍵轉折，並分清當時人的認知與後世的解釋。 |
| **調查型** | 地緣政治、衝突與爭議 | 參照戰地記者查證報道的方法，分清各方聲稱甚麼、紀錄證明甚麼、獨立資料又證實了甚麼。沿事件和利益關係分析局勢，保留未能核實之處。現場細節必須有出處。 |
| **敘事型** | 英文人物傳記、創辦人研究 | 以紀實傳記的方法，圍繞改變人生方向的決定展開：當時面對甚麼處境、有哪些選擇、行動帶來甚麼後果。經歷、言論和轉折都須有紀錄，再由人物連繫至時代。 |
| **分析型** | 中英文商業、科技行業研究，如 NVIDIA | 採用財經和科技深度報道的寫法，先提出核心判斷，再拆解硬件、軟件生態及客戶依賴。比較優勢、代價與替代方案，解釋哪些因素可能削弱現有地位，讓讀者看清判斷成立的條件。 |
| **解釋型** | 科技原理、哲學思想，如存在主義 | 參照科普作者的講解方法，由具體問題帶出概念和邏輯。術語首次出現便解釋，再用分歧、反例及適用範圍，檢驗讀者剛建立的理解。 |
| **評論型** | 產品、作品與思想評價 | 先準確介紹評論對象，再交代評價標準，與可信的替代選擇比較。結論須解釋為何作此評價，同時交代合理的不同意見，以及哪些證據可能令評價改變。 |

文體會影響整篇文章的安排。歷史研究要交代時代條件，傳記要給關鍵經歷足夠篇幅，科技分析則要說清原理與實際限制。各節可按材料選擇寫法，全文仍以一種主要文體貫穿。

中英文各有獨立的編輯規則。簡體中文着重自然表達。香港繁體採用本地用詞及書面語。英文則檢查措辭、句子節奏和論證銜接。無論哪種文體，數字、引文和必要的限定條件都須忠於證據。

## 初稿完成後，再過兩輪編輯

**Rewild 負責去 AI 味。** 英文、簡體中文及香港繁體各有內置規則，處理空話、機械式過渡、重複句式、刻意排比，以及千篇一律的段末總結。多餘句子會刪去，生硬段落會重寫，並保留研究報告應有的專業語氣。

修改後還要對照原稿，確認數字、引文、引用、限定條件和因果關係沒有走樣。「可能」不能改成「一定」。

**另一輪重新評審內容質素。** 最終稿按八項準則評分：是否回答問題、證據強度、證據覆蓋、推理完整性、反證處理、解釋深度、實際價值及文字清晰度。每項須達 4/5 分。有實質問題便退回修改。

長文結構亦會再看一次。各節有沒有重複同一套寫法？重要問題與次要問題是否佔了相同篇幅？讀完一節，讀者究竟多明白了甚麼？

自動檢查只適用於當時受檢的版本。正文其後有改動，便須重做檢查。自動工具不可用時，由智能體逐項核實及審閱。

## 交到你手上的報告

內置 **11 套視覺模板**，適用於商業、人文歷史、科技、生態等題材。預設提供兩份內容相同的 PDF：一份採用 Executive，另一份按題目自動配搭風格。你亦可以指定模板。

PDF 包括封面、目錄、分章正文和可點擊的引用。產生檔案後會重新開啟，檢查文字、連結、字體、分頁及內容超出版面的情況，亦會查看頁面圖像，修正裁切和空白頁等問題。版式選項見[模板說明](references/pdf-templates.md)。

交付內容包括：

- **完整長篇報告**：中文 5,000–10,000 個非空白字元。英文 7,500–15,000 詞。透過補充證據及深入分析達到篇幅要求。
- **經檢查的 PDF**：製作目標約十頁或以上，實際頁數視乎語言及版式。
- **Markdown 原稿**：方便搜尋、摘錄、修改及再用。
- **緊貼相關論點的來源引用**：方便核對證據，繼續閱讀原始資料。

## 為甚麼一次研究可能要半小時？

由題目到成品，要完成以下工作：

**拆解題目 → 分工搜尋 → 評估來源 → 交叉核實與反證 → 整合證據 → 總編輯撰稿 → Rewild 編輯 → 內容複審 → PDF 製作及目視檢查**

遇到兩個來源說法矛盾，就要追查原始紀錄。寫稿時發現關鍵論據不足，便要補做研究。文字修改若影響結論，也須重新核對。

複雜題目可能需時半小時或更久，實際時間取決於題目、資料是否容易找到、所用模型及運行環境。

## 開始第一份研究

將 GitHub 儲存庫連結或 ZIP 檔案交給支援 skill、聯網研究及本機執行的智能體，告訴它：

> 幫我安裝這個 skill。

智能體會按 [INSTALL.md](INSTALL.md) 安裝所需環境，並驗證 PDF 產生功能。完成後便可提出題目，例如：

> 用 Alexandria 深入研究：為甚麼明朝財政長期受制於白銀？從制度、貿易和地方管治解釋，寫成中文報告。

> 用 Alexandria 研究 NVIDIA 的競爭優勢。拆解硬件、軟件生態及客戶依賴，並檢驗最可能削弱其優勢的因素。

> 用 Alexandria 解釋存在主義。說清楚它想回答的問題、主要分歧，以及它如何影響普通人的選擇。

如有特別想了解的角度、目標讀者或時間範圍，可以一併交代。只有一個題目，也可以開始。
