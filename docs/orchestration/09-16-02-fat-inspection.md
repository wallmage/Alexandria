FAT (a candidate) = an item that is at least one of:
- `no-effect`: when its condition is true, fixing it makes the report no better (no reader-visible, evidence, argument, prose or PDF improvement), or its condition is almost always a false positive on a good report and a true positive has no quality effect;
- `over-strict`: a threshold, cap, count or required field stricter than quality needs, so good reports get reworked (name the threshold and what a correct report trips on);
- `duplicate`: the same property checked twice (two families, two modules, a doc rule plus a code check), producing two messages or two fixes for one defect — the weaker copy is the candidate;
- `dead`: unreachable from the HEAD `SKILL.md` path and the `alx` flow (a subcommand, flag, function, receipt field, doc section or test harness nothing reaches), or prose the model is never told to read;
- `burden`: a wait (timeout, retry, live re-fetch, render pass), a refusal, an extra command, an extra agent turn, or a ceremony (a status line the model must read, a file it must not read, a note it must write) whose only purpose is process, not the report.
AND its cost is real: seconds of wall time, an extra command, an extra agent turn, tokens the model must read, a false positive the model must investigate, or a refusal. Cost is measured on the fixture (§K) or counted (commands, lines, tokens), never guessed.
