## 2. Goal
Any harness (Claude Code, Codex, WorkBuddy/CodeBuddy, Cursor) with any model tier (incl. GLM-Flash / DeepSeek-Flash / Sonnet-tier) delivers Markdown + 2 PDFs in ≤ 60 min wall-clock without verification loops, and never fails to deliver. Anti-fabrication property, unconditional on every delivery path: no sentence in the delivered report rests on a claim that failed a fabrication-class check (§6.10 Class F). Under time pressure the report gets shorter or more qualified; it never gets less true.

## 3. Non-goals
- Changing research/editorial standards (archetypes, editorial modes, PDF templates, rewild profile content).
- New PDF features. Offline (no-network) research.

## 4. Principles
- P1 Tooling carries rules; SKILL.md carries the sequence.
- P2 Verbatim by construction: extracts are copied from cached fetched text via a tool; a source exists in the ledger only after it was fetched and decoded; a claim exists only after its extracts were probed against that cache.
- P3 One check, all findings, grouped, with the fix; hard vs warn; never one family per run.
- P4 Receipts once, at the end, by one idempotent command; iteration never touches receipts.
- P5 Budget-aware degradation that drops scope, never integrity.
- P6 Environment-tolerant: charset sniffing, unreachable ≠ mismatch, fetch cache, consistent CLI, no fictional flags, all free text enters via files.
- P7 Integrity: control chars, lost quotations, U+FFFD, truncated files, detached caches detected by every check.
- P8 State on disk survives compaction (`alx status`, `worklog.md`, `.alx/state.json`).

## 5. Architecture
New single entry point `scripts/alx.py` (`"$ALEXANDRIA_PYTHON" "$SKILL_ROOT/scripts/alx.py" <subcommand>`), thin over the existing modules used as libraries. Existing scripts keep their standalone CLIs and default behaviors (tests updated only where §7 changes a rule); new modes are opt-in flags. SKILL.md becomes a ≤150-line runbook (§8). Workspace per report directory:

## 6. `alx` subcommands (interfaces pinned)
Free text enters only via files; CLI args are paths, ids, enums, one short keyword (`find`). Every command appends `<ts> <cmd> <summary>` to `worklog.md`; the last printed line is `elapsed <m> min, remaining <m> min`. Every printed remedy is either an `alx` command that `alx`'s own parser accepts (parse-tested, D14) or one imperative from the closed list {`set field <name> in <file>`, `extend the quote in <file>`, `delete paragraph <n> of report.md`}. Exit 0 = no hard findings.

6.1 `init DIR --lang {en,zh-CN,zh-HK} --subject FILE [--archetype {person,organization,artifact,event,concept,system,hybrid}] [--reader FILE] [--budget-minutes 60]`
Creates the layout; `report.md` skeleton (H1 placeholder, standfirst blockquote placeholder, strict-locale date line == `ledger.report_date`); `ledger.json` v4 skeleton (brief from files, `report_date`, `report_language`, empty arrays, synthesis skeleton); for `person` archetype `--subject-status {living,recently_deceased,deceased,unknown}` is required and writes `people[0]` primary_subject with that status; while it is `unknown`, `claim add` refuses person-linked claims with HARD "set people[0].living_status via `alx ledger merge`" (harm review is demanded only for living/recently_deceased/unknown persons, as today); `.alx/state.json` with `start_time`, `deadline = start + budget`. Refuses if a ledger exists (`--force` resets). Prints the next command.

6.2 `fetch URL... | --id S<n> --refresh` `[--provenance P] [--type T] [--role R...]`
Per URL: non-http(s) rejected; `http://` → try `https://` first, record the http form as an alias. Fetch via `source_fidelity.fetch_document` (§7.2.1), which reuses today's transport (`validate_public_http_url`, DNS pin, port 443, no credentials, private-address block, redirects locked to the same registrable domain). Outcomes, one line each:
- `S7 OK 12457 chars gb18030 "<title>" <final_url>` → source upserted: `url=final_url`, `aliases=[requested url, redirects...]`, title, publisher = registrable-domain label, `source_family` = registrable domain, `accessed` = today, `published` from meta tags else null, `provenance: "unverified"` (existing enum; every independence and key-claim rule treats it as interested, tested; D13), `evidence_type` from `--type` else `news_report`, `roles` from `--role` else `["independent_analysis"]`, `accountability_basis` from `--accountability` else `none`; cache written.
- `S7 UNREACHABLE (<class>: <reason>) — not added` where class ∈ {dns, timeout, tls, http-<status>, plaintext-http, oversize, redirect-loop}.
- `S7 UNDECODABLE (<declared charset>) — not added`.
- Redirect leaving the registrable domain → `UNREACHABLE (cross-domain-redirect → <final url>)`; the agent fetches the printed final URL as a new source if it wants it.
- Duplicate URL/alias → prints existing id. `--id S7 --refresh` re-fetches the ledger URL, refreshes cache + `accessed`; if the text sha changed, prints `S7 text changed; claims C3,C9 need re-probe` and `check` re-probes.
`source set S<n> [--provenance P] [--type T] [--role R...] [--accountability A] [--published DATE] [--undated-reason FILE]` edits classification fields only; identity fields (url, aliases, text_sha256, accessed) are fetch-owned.

6.3 `find S<n> KEYWORD [--context 160] [--max 5]` and `show S<n> [--start i --end j]`
Verbatim windows from the cache, sentence-bounded, no ellipsis, ≤ 300 chars, numbered; paste-ready.

6.4 `claim add FILE.json...`
FILE = one or many **claim-input** objects (schema `references/claim-input.schema.json`, new): required `claim_id` (`C<n>`, unique; missing → HARD "add claim_id"), `claim`, `kind`, `importance`, `source_evidence[] {source_id, extract_or_location}`; optional `as_of`, `time_sensitive`, `person_ids`, `person_claim_role`, `person_claim_assessment`, `supports`, `contradicts`, `confidence`, `limitations`, `what_would_change`, `derived_assertions`, `evidence_of_absence`, `human_harm_review`, `reasoning` (required when kind=analysis), `assumptions` (required when kind=estimate), `responds_to_claim_ids` / `resolves_claim_ids` (required for response/resolution roles), `report_paragraph` (int, for §6.7c binding). The conditional requirements mirror the ledger schema and are reported per claim with the missing keys. `alx` expands to a full v4 claim: `source_ids` derived, `include_in_report: true`, `triangulation` computed from merged families (`met`/`limited`), `verified_at` = cache fetched_at, `report_excerpts` left empty until binding. Per claim, all of the following run and **all** findings print (no short-circuit): claim-input schema → extract length (ruling R13: a whole extract under 20 normalized chars, under 10 when it contains CJK, is a WARN "extend the quote" on the whole extract only — never on a piece, never blocking; an empty extract stays HARD) → quantities/status/direction vs its own extracts (validate_ledger functions) → each segment probed against `sources/S<n>.txt` (source_fidelity probe functions, full coverage) → person rules (people must exist; `ledger merge` people first; R15: a claim naming a registered person's display name or alias has its `person_ids` auto-derived by `claim add` and `check --fix` — WARN naming what was linked, never HARD) → harm rules when a linked person is living/recently_deceased/unknown (the agent must supply `human_harm_review`; the message lists the missing keys). Upsert by `claim_id` only when no hard finding; failures print `C5 FAIL [family] message — fix: <pinned command or field>`.
`claim drop C<n> [--apply]`: without `--apply` prints the plan: the paragraph mapped to C<n> (§6.7c), every other claim mapped to that paragraph (they are dropped too), and every surviving claim whose `supports` names a dropped claim (HARD until re-pointed). With `--apply`: deletes that paragraph from `report.md`, moves the dropped claims from `claims` to `excluded_claims[]` (new ledger array: full claim + `reason` + `dropped_at`; excluded claims are never validated for evidence, never counted for coverage/synthesis, and may not be named in any surviving `supports`), removes synthesis references, regenerates the Sources section. `check` HARDs `leftover-prose` when an excluded claim's mapped paragraph text is still present. This is the Class-F scope-dropping remedy (§6.10).
`claim bind C<n> --paragraph N`: sets the claim→paragraph assignment used by §6.7c.

6.5 `ledger merge PATCH.json`
Deep-merges only `brief`, `people`, `coverage`, `synthesis`. Keys `claims`/`sources` in the patch → HARD "sources only via fetch/source set; claims only via claim add". Runs §6.7(b) afterwards.

6.6 `snapshot [--iter] [--restore]`
Write-once copy to `report.pre-rewild.md`; `--iter` writes `report.pre-rewild.iter<k>.md`; `--restore` overwrites `report.md` with the latest snapshot (the pinned remedy for quotation-lost/control-char findings).

6.7 `check [--fix]`
Always runs everything offline, then prints grouped findings (format below). Sections:
(a) integrity: UTF-8; no C0 except \t\n\r; no U+FFFD; H1, standfirst blockquote, strict date line == ledger.report_date; length counted the validator's way with thresholds; if any snapshot exists: every quoted span (「」『』“”‘’ and straight "…" ≥ 4 chars) of the latest snapshot still present verbatim → HARD `quotation-lost` with remedy `alx snapshot --restore`.
(b) ledger: validate_ledger grouped (§7.1); cache binding: every source has `sources/S<n>.meta.json` with `url == ledger url` and `text_sha256 == sha(sources/S<n>.txt)` else HARD `cache-detached` (remedy `alx fetch --id S<n> --refresh`); provenance `unverified` on any source cited by a key/central claim → HARD (remedy `alx source set`).
(c) binding: every link URL in the body, after normalization (lowercase scheme/host, strip fragment and `utm_*`, trailing slash), ∈ ∪{url, aliases} of ledger sources → else HARD with the nearest ledger URL; every `include_in_report` claim maps to exactly one paragraph: from `report_paragraph`/`claim bind` when set, else auto-derived only when exactly one body paragraph links to one of the claim's foundation URLs (else HARD "ambiguous: run `alx claim bind C5 --paragraph N`; candidates: 12, 19"); with `--fix` the excerpt (first 60 chars of the mapped paragraph) is written to `report_excerpts`; `check` prints the full claim→paragraph table; Sources H2 must be last and equal the cited-source list (with `--fix`, regenerated from the ledger as `[title](url)` in first-citation order).
(d) fidelity-offline: every extract segment probed against cache (full coverage); MISMATCH HARD; missing cache → HARD `cache-missing`.
(e) rewild: complete offline evaluation of `rewild_gate` in `--check` mode when a snapshot exists: integrity, semantic fidelity (negation/direction/causal/association, HARD, quote-masked, citation-stripped), regional (HARD), AI-vocabulary (HARD, length-scaled, quote-masked), other style (WARN).
(f) reviews: complete offline evaluation of both notes' gate checks (schema, completeness, scores ≥ 4, critical findings fixed, disclosure excerpts located, per-claim support disposition for every retained claim→paragraph mapping in the content note) and snapshot freshness (§6.8). Missing or stale content review → Class F (remedies: `alx review start content [--iter]`, or `alx review restore content` which reverts `report.md` and `ledger.json` to the reviewed copies). Missing or stale rewild review → Class A.
Output:
```
=== HARD 7 (blocks issue) ===
[ledger/quantity] 3
  C8: claim asserts n:1918; S16 extracts offer d:1918-01 only. Fix: quote a sentence containing the bare figure via `alx find S16 1918`, or reword the claim to the dated form. Remove: `alx claim drop C8`.
  … (max 5 per family, then "+N more")
=== WARN 11 === …
=== STATUS: check #2, elapsed 31 min, remaining 29 min. Next: fix HARD then `alx check`. At remaining ≤ 15 min apply every "Remove:" remedy and run `alx issue --deliver`. ===
```
`--fix` applies only mechanical repairs: source_ids derivation, family from domain, excerpt writes for unambiguous mappings, Sources regeneration, `accessed`/`verified_at` refresh from cache meta, date-line whitespace. Never claim text, extracts, or prose.

6.8 `review start {rewild,content} [--iter]` / `review finish {rewild,content}`
`start`: copies `report.md` (+ `ledger.json` for content) to `.alx/reviews/<kind>/<k>/`, records their hashes in `state.json`, writes the note skeleton (`reviews/<kind>.json`) bound to those hashes with the finding/score sections empty; prints what the reviewer must do (blind review protocol from `references/rewild-gate.md` / §13 of content-quality). `--iter` (k+1) prints the paragraph-level diff since snapshot k and creates an iteration entry scoped to those paragraphs. `finish`: validates completeness (all sections filled, hashes intact); refuses otherwise with the missing items. `review restore {rewild,content}`: overwrites `report.md` (and `ledger.json` for content) with the latest finished snapshot copies.
Freshness rule used by `check`(f) and `issue`: current inputs must equal the latest finished snapshot except for **mechanical deltas**: Sources section regeneration, `report_excerpts`, `accessed`/`verified_at`, whitespace, date-line normalization, Markdown link insertion/removal with unchanged visible text. Deletions performed by `claim drop --apply` and the machine-written Verification note (§6.9) are also mechanical. Any other paragraph added/removed/changed (masked, paragraph-split diff) → HARD "re-review required: `alx review start <kind> --iter`". Ledger changes beyond mechanical (any claim/source field other than the list above) → content re-review required. `issue` stamps the exact current hashes into the notes only when this rule passes.

6.9 `issue [--deliver] [--sample-size 8]`
Precondition: a snapshot exists; if none, `issue` creates `report.pre-rewild.md` identical to the current report and records `humanization: none` (Class A note). Steps, in order:
1. Fresh full `check`. Any Class-F finding → refuse and print them, regardless of `--deliver`. With `--deliver`, before refusing, `issue` first auto-applies `claim drop --apply` for every claim-level Class-F finding and `snapshot --restore` for quotation-lost/control-char findings, then re-runs `check`; only findings that survive that pass refuse.
2. Online source fidelity on the weighted sample (§7.2.5), deadline-bound (§6.11); live text refreshes the cache of every fetched source; then **every** claim using a refreshed source is re-probed offline. Online MISMATCH, offline mismatch after refresh, or changed probe context (§7.2.6) → Class F for those claims (with `--deliver`: auto `claim drop --apply` for them, then continue; without: refuse). Receipt `receipts/source-fidelity.json`.
3. Verification note: when `delivery-notes` (so far) or `disclosure_required` is non-empty, `issue` inserts the machine-written, language-templated note paragraph immediately before the Sources H2 in `report.md` (idempotent: replaces a previous note). This is the only prose `alx` ever writes.
4. Review freshness (§6.8) for both notes; stamp current hashes. rewild_gate → `receipts/rewild.json`; content_gate → `receipts/content.json`; validate_report `--fast --final-once` (in-process receipt verification; no second fetch).
5. `receipts/issue.json`: hashes of `report.md`, `ledger.json`, every receipt and note, checker versions, timestamp, `delivery_notes` (may be empty).
Failure semantics: any Class-F finding in any step refuses (`--deliver` or not) after the auto-remedies above. Without `--deliver`, any Class-A failure in steps 2–4 aborts before step 5 and writes no `issue.json`. With `--deliver`, Class-A failures are recorded in `receipts/delivery-notes.json` (machine-written from the findings) and the run continues; when remaining time < reserve, step 2 is skipped as Class A. A receipt is never fabricated; stale receipts are overwritten.

6.10 Finding classes
- **Class F (fabrication/integrity; never waivable):** quantity/status/direction uncovered or contradicted; extract MISMATCH offline or online; changed probe context; cache-missing/cache-detached; quotation-lost; control chars/U+FFFD; link-not-in-ledger; leftover-prose; ambiguous or missing claim→paragraph binding; claim without probed extracts; surviving `supports` naming an excluded claim; key claim on `unverified`/interested-only sources; person/harm rules; rewild semantic fidelity and regional; missing or stale content review; schema-invalid ledger. **Default: any HARD family not listed under Class A is Class F.** Every Class-F remedy line names a scope-dropping command (`claim drop --apply`, `snapshot --restore`, `review restore content`).
- **Class A (availability/tooling; waivable by `--deliver`):** live source unreachable/undecodable beyond quorum; receipt tooling errors; renderer/rasterizer failures; rewild review missing or stale; `humanization: none`; style warnings; AI-vocabulary above threshold; length below floor; Sources-section or H1/standfirst/date-line formatting defects that `check --fix` could not repair.

6.11 Deadline propagation
`state.json.deadline` binds every command: network per-source timeout 10 s, 1 retry; `fetch` batch stops when remaining < 20 min and prints it; `issue` online phase capped at min(4 min, remaining − 8 min reserve); rewild checker subprocess 120 s; md_to_pdf and rasterizer subprocesses 90 s each with backend fallback; when a step times out it is a Class-A finding. `status`/`check` print remaining minutes; at remaining ≤ 15 min every command prints the degradation instruction.

6.12 `render [--template T]`
Requires `receipts/issue.json` whose recorded hashes equal the current `report.md` and `ledger.json`; otherwise refuses with "run `alx issue` (or `alx issue --deliver`)". There is no receipt-free render path in `alx`. md_to_pdf runs with `--issue-receipt` (offline hash verification only; no gate re-execution, no network) for Executive + `select_adaptive_companion()`; PDF validation; rasterization with backend fallback; prints PDF paths and contact sheets. Always-deliver is therefore `issue --deliver` then `render`, never `render` alone.

6.13 `status`
Elapsed/remaining, phase checklist (sources n, claims n, snapshot?, reviews finished?, receipts?, PDFs?), last check summary, next command.

## 7. Gate behavior changes (standalone scripts too)
7.1 validate_ledger.py
- Output grouped by family with counts; ≤ 5 instances per family then "+N more"; per-family fix line; summary line. Library API `collect_findings(ledger) -> list[Finding(family, severity, ids, message, fix, remove)]`.
- (R28) Severity is two-valued; the table below replaces the old warn tier / "hard: everything else" default and Class A. **HARD** (blocks `issue`; `issue --deliver` applies its Remove remedy, then issues) = fabrication and evidence integrity only: `ledger/quantity` (Arabic-digit figures, percentages, currency, dates; CJK numeral words warn per R26), `ledger/status`, `ledger/direction` (keep the narrowed English trigger set: no bare `under|below|settled` without a numeric or legal carrier), `ledger/derived` (hard half: a derivation asserting what no source offers), `ledger/claim-input` (only missing/duplicate `claim_id`, empty claim text, empty `source_evidence`, empty extract, unfetched source — every conditional field is optional), `ledger/schema`, `ledger/reference` (only a `source_id` no fetched source carries), `binding/link-not-in-ledger`, `binding/leftover-prose`, `fidelity/mismatch`, `fidelity/cache-missing`, `fidelity/cache-detached`, `fidelity/rewild`, `integrity/control-chars`, `integrity/replacement-char`, `integrity/encoding`, `integrity|fidelity/quotation-lost` (a quoted span altered; a span removed entirely warns), `runtime/missing`.
- (R28) **WARN** (printed with its fix, recorded in the delivery notes, never blocks `issue`, `render` or `claim add`; carries no Remove remedy): `ledger/key-claim`, `provenance`, `portfolio`, `triangulation`, `host-conflict`, `source-family`, `source-ids`, `https`, `freshness`, `undated-reason`, `excluded-supports`, `coverage`, `synthesis`, `adversarial`, `date-granularity`, `extract-length`, `derived` (warn half), `reference` (non-source), `person` (unregistered id only — the harm rules, `person_claim_role`, `person_claim_assessment` and `human_harm_review`, are deleted per R25, and `ledger/harm` is gone); `integrity/structure`, `integrity/date-line`, `integrity/length` (both ends), `binding/claim-paragraph`, `binding/excerpt-missing`, `binding/sources-section`; every `rewild/*` and `review/*` and `content/*` family; `tooling/receipt`, `tooling/render`.
- Quantities: claim tokens `N日`, `N月`, `N月N日`, `N年`, `N年N月` normalize to date-fragment forms (`d:…-12`, `d:…-12-12`, `d:1936`, `d:1936-12`); a full date in an extract covers the fragments of itself; R14: a month-day or day fragment covers the claim's full date when the parts the extract omits (the year, and the month for a day fragment) appear elsewhere in that source — cached text, title or `published` — so a page that states the year once and then writes bare month-day dates is not a gate failure; without a cache the rule is unchanged; plain `n:` numbers are never covered by date components; NFKC-fold both sides; CJK sentence boundaries `，、！？：；。`; classifiers `個个項项名家次種种款位條条篇卷册冊`; message prints the claim form and the forms each inspected source extract offered.
- Messages state threshold and actual value; CJK minimum lengths halved (40→20) for rationale/justification/derivation. `source_ids` missing → derived (warn); one error per claim for extras. Same-host independence conflicts: all hosts in one pass with provenance per id. `undated_reason` failure prints accepted phrasings. HTTPS-only rule enforced here on `source.url` only (aliases may be http). `provenance: unverified` (existing enum) treated as interested/non-independent in every rule (tested).
- Docs: `report_excerpts` 40→10 aligned in evidence-recording.md.
- (R20–R24, amended R28) The protected-person messages are deleted with the harm rules: `person_claim_role`, `person_claim_assessment`, `human_harm_review` and the `ledger/harm` family no longer exist, and `ledger/person` warns only on an unregistered person id. Quantity coverage adds R14b (a month-day fragment covers a year-month claim under the R14 haystack) and R21 (a bare-year claim is covered by the same 4-digit number, years 1000–2999). Direction: the negation window stops at ASCII `.`/`;` too, and CJK carriers bind on a shared four-character phrase. Two `source_evidence` entries with one `source_id` are allowed (R22). Untested counterevidence is a warn with fix `set field synthesis.adversarial_tests, then alx ledger merge synthesis` (R23). `as_of` up to 1 day after `verified_at` is not a finding (R24).
- (R20–R24) §7.2 amendment: `probe_findings` takes the evidence entry to probe, so every entry of a multi-passage source is checked on its own; the caller iterates `source_evidence`, not `source_ids`.
- (R28) §7.2 family severities: HARD = `fidelity/mismatch`, `fidelity/cache-missing`, `fidelity/cache-detached`, `fidelity/rewild`, `fidelity/quotation-lost` (altered span). 7.2 source_fidelity.py
1. `fetch_document(url, *, cache_dir=None, refresh=False, timeout=10, deadline=None) -> FetchResult(status∈{ok,unreachable,undecodable}, reason_class, reason, text, charset, url, final_url, aliases, http_status, title, published, text_sha256)`; charset ladder: HTTP header → BOM → `<meta charset>` → `<meta http-equiv>` → utf-8 strict → gb18030; U+FFFD ratio > 1% → undecodable. Browser-like UA. Built on `default_fetcher`'s existing transport: `validate_public_http_url`, DNS pin, port 443, no credentials, private-address block; redirects only within the same registrable domain (cross-domain → unreachable(cross-domain-redirect) with the final URL in `reason`); v2 receipts still require `PRODUCTION_TRANSPORT`. TLS verification kept; TLS errors → unreachable(tls). Plain HTTP → unreachable(plaintext-http) with https suggestion.
2. Check statuses `verified | mismatch | unreachable | undecodable`, printed in separate sections.
3. Probes: every segment of the extract must appear (full coverage retained; no "first window + one" rule); an extract that occurs verbatim in the normalized document is one segment; otherwise it splits on author ellipses (… / ...); quote spans matched per glyph family, never across an ellipsis; quote-glyph families and CJK/ASCII comma/period folded on both sides; every non-empty piece must occur, whatever its length (ruling R13: punctuation-only pieces ignored; length is never a fabrication check).
4. `--cache-dir`: offline check reads cache; `--online` fetches and refreshes.
5. Receipt policy `weighted-source-evidence-v2`: sample top-N by weight; an unreachable/undecodable sampled pair is replaced by the next candidate for the same claim when one exists; issue when 0 mismatches AND unverified ≤ 25%; unverified listed with reason; central-judgment pairs unverified → `disclosure_required` and the Verification note names them. v1 receipts remain valid.
6. Context comparison (inside `issue` step 2 against the research-time cache, and in standalone online receipt validation): probe present and every recorded probe-context hash unchanged → verified; probe present but any context hash changed → HARD "S7 context changed since research; re-read" (never self-authorizing; the message quotes the changed window and flags correction markers `更正|撤回|訂正|勘误|correction|retract|erratum|update` when present); remedy `alx fetch --id S7 --refresh` then re-probe and re-confirm, or `claim drop --apply`. Whole-document hash equality is dropped.
7. CLI: remove the `--allow-unverified` sentence; add `--force`; print failing checks before refusing a receipt; `--explain C<n>` prints probes without fetching.

## 8. SKILL.md runbook (≤150 lines; replaces the body; frontmatter and INSTALL.md unchanged)
Purpose (3 lines) → non-negotiables (6 bullets: incl. "nothing ships that failed a fabrication check; under time pressure drop it") → **Steps** (each: goal, exact `alx` command, what to think about, time box) → **Rules for every model** → **Budget & always-deliver** → optional deep reads (archetype, editorial, rewild profile) "only if remaining > 40 min".
Steps: 0 verify runtime → 1 `init` (subject file; `--subject-status` for a person) → 2 search; `fetch` promising pages (target 8–15 OK; ≤ 15 min; `source set` for anything the subject controls) → 3 `ledger merge` people/coverage; `find` → `claims/*.json` (ids!) → `claim add` (12–30 claims) → 4 draft `report.md` (cite only ledger URLs) → 5 `check --fix`; fix HARD by the printed fix; re-run → 6 `snapshot`; humanize per profile quick checklist; `check` → 7 `review start rewild` → fill → `review finish`; `review start content` → fill → `finish`; `check` → 8 `issue` (or `issue --deliver`) → 9 `render`, look at the contact sheet → 10 deliver.
Rules for every model: never edit `report.md` after `snapshot` except through the humanize step and review-driven fixes (no snapshot = no prose edits); one command at a time; never edit `ledger.json` or anything under `.alx/`, `receipts/`, `sources/` by hand; never two edits to one file in one turn; never put report or claim text inside a shell command (write a file, pass the path); after any interruption run `alx status`; apply exactly the printed fix; when remaining ≤ 15 min stop fixing and run `alx issue --deliver` (it applies every Remove remedy itself), then `alx render`.
Budget: 60 min; checkpoints printed by `alx`; remaining ≤ 15 min → `issue --deliver` then `render`; there is no render without issue.
